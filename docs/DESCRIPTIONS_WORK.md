## 1. Зачем это

Карточка планеты в UI сейчас показывает данные: температуру, массу, состав, ядро. Это цифры. Игрок их видит, но не «проживает» планету.

Описания дают второе: мир, характер, историю. Один и тот же набор цифр может быть подан по-разному — как научный отчёт, как загадка, как приключение. Это делает планеты запоминающимися.

**Ключевой принцип:** детерминизм. Одна планета — один текст (в рамках текущего пула). Разные планеты — разные тексты. Достигается через хэш от `planet.id`.

**Связь с аномалиями:** `config/anomalies/` — это редкие «нарушения физики» с собственными текстами. `config/descriptions/` — это базовые описания, которые получает **каждая** планета.

---

## 2. Формат файлов

Каждый файл — JSON с одним массивом. Формат записи:

```json
{
  "openings": [
    {
      "text": "Первый абзац.\n\nВторой абзац.",
      "requires": ["old", "has_satellites"]
    }
  ]
}
```

или для концовок:

```json
{
  "closings": [
    {
      "text": "Один абзац.",
      "requires": []
    }
  ]
}
```

**Ключи верхнего уровня:** `openings` — зачины, `closings` — концовки.
**Поля записи:** `text` — текст, `requires` — массив тегов (пустой = работает всегда).

---

## 3. Список тегов (ФИНАЛ, проверено по коду)

Все теги вычисляются в `internal/generator/planet/descriptions_tags.go` из `DescriptionContext`.

### Спутники
- `no_satellites` — `moons == 0`
- `has_satellites` — `moons > 0`
- `many_satellites` — `moons >= 5`

### Биосфера
- `no_biosphere` — `life == false`
- `has_biosphere` — `life == true`
- `inhabited` — `population > 0`

### Орбита
- `inner_orbit` — `orbit_index <= 2`
- `outer_orbit` — `orbit_index >= 5`

### Температура (K)
- `cold` — `temperature < 220`
- `temperate` — `220 <= temperature <= 380`
- `hot` — `temperature > 380`

### Возраст (`core.Age`, млрд лет)
- `young` — `< 2.0`
- `old` — `> 6.0`

### Плотность
- `low_density` — `< 0.5`
- `high_density` — `> 1.5`

### Масса
- `massive` — `> 5.0` (для газовых гигантов — `> 100`)

### Ядро
- `ice_core`, `metallic_core`, `silicate_core`, `exotic_core` — по `core.Type`
- `active_core` — `core.Activity > 40`
- `radioactive_core` — `core.Radioactivity > 50`

### Криовулканизм
- `cryovolcanic` — `ShareOf(SurfaceGlaciers) >= 30` **и** `core.Activity > 50`

### Подповерхностный океан
- `has_subsurface_ocean` — `hydrosphere == "подлёдная"` **или** (`temperature < 250` **и** `water_percent > 30`)

### Атмосфера
- `no_atmosphere` — `atmosphere == "разряженная"`
- `dense_atmosphere` — `atmosphere == "плотная"` **или** `"парниковая"`
- `toxic_atmosphere` — `atmosphere == "ядовитая"`

### Газовый гигант
- `is_gas_giant` — `ctx.IsGasGiant == true` (задел, пока в текстах не используется)

**Правило:** если тег не может быть вычислен — условие считается невыполненным.

## 4. Детерминированный выбор

При показе планеты:

1. **Определяем её группу** — по `type` в JSON планеты. `typeToFolder()` переводит геймдизайнерский тип (`TypeIce = "ледяная"`) в имя папки (`icy`).
2. **Собираем подходящие зачины** — фильтрация по `requires` через `matchesAll`.
3. **Считаем индексы:**
   ```
   openingIdx = hashIndex(planetID + ":opening", len(filteredOpenings))
   closingIdx = hashIndex(planetID + ":closing", len(filteredClosings))
   ```
   Хэш — FNV-1a, 64 бита.
4. **Собираем текст:**
   ```
   openingText + "\n\n" + closingText
   ```
5. **Fallback.** Если ни зачин, ни концовка не подошли — выбирается нейтральный текст из `fallbackVariants` (7 вариантов) по хэшу от `planetID + ":fallback"`. В проде сейчас не срабатывает.

## 4.1. Автопоиск файлов

При старте сервера `LoadDescriptions("config/descriptions")` сканирует папки типов, читает все `openings_*.json` и `closings_*.json` (сортировка по имени), складывает в плоские срезы. **Хардкод-списка файлов нет.**

**Что это даёт:** положил `openings_06.json` → `git push` → Amvera пересобрала и перезапустила → файл подхватился. Кода не касаемся.

**Маппинг тип → папка** задан в `descriptions_mapping.go` (функция `typeToFolder`). Если добавится новый геймдизайнерский тип — надо будет добавить строчку в этот маппинг.

**Что НЕ делаем:** горячий reload через `fsnotify`. Перезапуск сервера обязателен.

**Кэш:** загруженные тексты в памяти под `RWMutex`, после старта — только чтение.

---

## 4.2. Детерминизм при расширении пула

**Что гарантируется:** одна планета → один текст при текущем пуле (между запросами и перезапусками).
**Что не гарантируется:** «навсегда» при добавлении файлов. Формула `hash % N` при росте `N` может перенаправить планету.

**Решение:** принято как есть. Хранить выбор в БД — не сейчас.

**Дополнительно:** планеты, сгенерированные до деплоя системы описаний, сохранили в БД старые хардкод-описания (или fallback, если новый код отработал в момент генерации). Перегенерация описаний задним числом не делается — только для новых планет.

**Итого по логу прода:** 11 типов, 705 зачинов, 690 концовок.

**Про «лишние» записи:** у нескольких типов зачинов на 1–3 больше, чем планировалось. Это не баг — записи уникальны, просто чуть больше. Решено оставить как есть.

**Правило расширения:** в скелете (30+30) теги редкие (~15 без тегов, ~10 с одним, ~5 с двумя). При расширении до 150+150 можно добавлять плотнее тегированные тексты.

## 8. Стиль и голос каждого типа

### `gas_giant` — величие и тайна
Торжественный, философский, отстранённый. Масштаб, тайна, сравнение с известным.

### `icy` — тишина и хрупкость
Сдержанный, contemplative, почти шёпот. Холод как покой, медленность, скрытое под коркой.

### `oceanic` — движение и жизнь
Живой, динамичный, иногда обещающий. Вода как источник и среда.

### `volcanic` — агрессия и созидание
Энергичный, иногда жёсткий. Огонь как разрушение и начало.

### `desert` — суровость и время
Спокойный, меланхоличный. Засуха, ветер, память о воде.

### `glass` — хрупкость и радиация
Холодный, отстранённый. Стекло, отражение, катастрофа.

### `metal` — тяжесть и структура
Технический, точный. Металл как материал и основа.

### `organic` — жизнь во всех формах
Тёплый, наблюдательный. Биология, симбиоз, удивление.

### `rocky` — обычность и надёжность
Спокойный, рабочий. Камень как база, вариативность.

### `radioactive` — опасность и энергия
Настороженный, но с интересом. Радиация, свечение, ресурсы.

### `earthlike` — дом
Тёплый, приветливый, «свой». Жизнь, воздух, вода.

## 9. Правила работы

**Формат ответа:**
- Один файл — один ответ.
- 30 записей на файл.
- Всё оборачивать в четыре обратных кавычки.
- После каждого файла — ждать «дальше».

**Правило скелета:**
- ~15 записей с `requires: []`, ~10 с одним тегом, ~5 с двумя.
- Утверждения о жизни — только с `has_biosphere` / `inhabited`.

**Стиль текстов:**
- Научно-популярный, не сухой.
- Без штампов («загадочный мир», «таинственная планета»).
- Конкретика лучше абстракции.

**Ресурс:**
- 30 текстов за раз — рабочий максимум.
- После 5–6 файлов подряд — пауза.

**Правило про длину файлов кода:** если файл больше 200–300 строк — делить на логические. Это правило из `PROMPT.md`, применяется и к описаниям, и к коду.
