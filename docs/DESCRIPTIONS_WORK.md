## 1. Зачем это

Карточка планеты в UI сейчас показывает данные: температуру, массу, состав, ядро. Это цифры. Игрок их видит, но не «проживает» планету.

Описания дают второе: мир, характер, историю. Один и тот же набор цифр может быть подан по-разному — как научный отчёт, как загадка, как приключение. Это делает планеты запоминающимися.

**Ключевой принцип:** детерминизм. Одна планета — один текст навсегда. Разные планеты — разные тексты. Достигается через хэш от `planet.id`.

**Связь с аномалиями:** `config/anomalies/` — это редкие «нарушения физики» с собственными текстами. `config/descriptions/` — это базовые описания, которые получает **каждая** планета. Оба паттерна похожи, но аудитория разная: аномалии — исключение, описания — правило.

## 2. Формат файлов

Каждый файл — JSON с одним массивом. Формат записи:

```json
{
  "openings": [
    {
      "text": "Первый абзац.\n\nВторой абзац.",
      "requires": ["old", "has_satellites"]
    }
  ]
}
```

или для концовок:

```json
{
  "closings": [
    {
      "text": "Один абзац.",
      "requires": []
    }
  ]
}
```

**Ключи верхнего уровня:**
- `openings` — зачины, 2 абзаца, ~60–80 слов.
- `closings` — концовки, 1 абзац, ~25–40 слов.

**Поля записи:**
- `text` — сам текст. Внутри `\n\n` для разрыва абзацев.
- `requires` — массив тегов. Если хоть один не выполняется для планеты — запись не подходит. Пустой массив = работает всегда.

## 3. Список тегов (ФИНАЛ, проверено по коду)

Все теги вычисляются из `Properties` (см. `internal/generator/planet/properties.go`) или из данных, которые доступны рядом (`orbit_index` из БД, `is_gas_giant` / `is_radioactive` из классификатора).

### Спутники
Поле `moons` (int).
- `no_satellites` — `moons == 0`
- `has_satellites` — `moons > 0`
- `many_satellites` — `moons >= 5`

### Биосфера
Поле `life` (bool) — единственный надёжный источник про жизнь. `biosphere` (string) местами захардкожена и не отражает реальность. `habitable` — про возможность, а не факт.
- `no_biosphere` — `life == false`
- `has_biosphere` — `life == true`
- `inhabited` — `population > 0`
- Следствие: `inhabited` → всегда `has_biosphere` (в коде `population` генерится только при `life && habitable`).

### Орбита
`orbit_index` — из БД, 1-based.
- `inner_orbit` — `orbit_index <= 2`
- `outer_orbit` — `orbit_index >= 5`

### Температура (K)
- `cold` — `temperature < 220`
- `temperate` — `220 <= temperature <= 380`
- `hot` — `temperature > 380`

### Возраст
Берём **`core.Age`** (млрд лет) — `system_age` в `Properties` не сохраняется, но копируется в ядро при генерации.
- `young` — `core.Age < 2.0`
- `old` — `core.Age > 6.0`

### Плотность (в единицах Земли)
- `low_density` — `density < 0.5`
- `high_density` — `density > 1.5`

### Масса (в единицах Земли)
- `massive` — `mass > 5.0` (для газовых гигантов — `mass > 100`)

### Ядро
Поле `core` — **значение, не указатель**, `core == nil` не бывает. Тег не выполняется, если `core.Type` не совпадает.
- `ice_core` — `core.Type == "ледяное"`
- `metallic_core` — `core.Type == "металлическое"`
- `silicate_core` — `core.Type == "силикатное"`
- `exotic_core` — `core.Type == "экзотическое"`
- `active_core` — `core.Activity > 40` (эквивалент `core.IsActive()`)
- `radioactive_core` — `core.Radioactivity > 50` (эквивалент `core.IsRadioactive()`)

### Криовулканизм (для ледяных)
- `cryovolcanic` — `ShareOf(SurfaceGlaciers) >= 30` **и** `core.Activity > 50`
- Порог 30 выбран как компромисс: планета должна быть «по-настоящему ледяной», а не «сборной солянкой, где льда чуть больше остальных». Калибруется одной константой при необходимости.

### Подповерхностный океан (для ледяных)
- `has_subsurface_ocean` — `hydrosphere == "подлёдная"` **или** (`temperature < 250` **и** `water_percent > 30`)
- Требуется добавить `Hydrosphere string` в `Properties` (заполнять из `archetype.Hydrosphere`). Правка — 2 строки в `properties.go`, делаем при доработке кода.

### Атмосфера
Значения подтверждены по `planet_archetypes.json`: `плотная`, `парниковая`, `ядовитая`, `облачная`, `азотно-кислородная`, `углекислая`, `туманная`, `разряженная`, `метановая`, `азотная`, `электрическая`.
- `no_atmosphere` — `atmosphere == "разряженная"`
- `dense_atmosphere` — `atmosphere == "плотная"` **или** `"парниковая"`
- `toxic_atmosphere` — `atmosphere == "ядовитая"`
- **Важно:** значение `""` в коде не встречается — атмосфера есть всегда, вопрос только какая. Тег `no_atmosphere` означает «разреженная атмосфера», а не «её нет». Имя оставлено по традиции. Опечатка `"разряженная"` → `"разрежённая"` — см. TODO в разделе 10, вопрос 15.

**Правило:** если тег не может быть вычислен (например, `core.Type` не совпал) — считаем, что условие не выполнено, и такая запись не выбирается.

**Теги добавляются по мере необходимости.** Если при написании текстов появляется новый признак, который хочется использовать — добавляем сюда и в код.

## 4. Детерминированный выбор

При показе планеты:

1. **Определяем её группу** (по геймдизайнерскому типу `type` в JSON):
   - `gas_giant` — если `is_gas_giant` (поле в JSON газового гиганта)
   - `icy` — если `type == TypeIce` («ледяная»)
   - `oceanic` — если `type == TypeOceanic` («океаническая»)
   - `radioactive`, `earthlike`, `volcanic`, `desert`, `glass`, `metal`, `organic`, `rocky` — аналогично.

2. **Собираем список зачинов**, подходящих по `requires`. Отдельно для openings и closings.

3. **Считаем индексы:**
   ```
   openingIdx = hash(planet.id + ":opening") % len(filteredOpenings)
   closingIdx = hash(planet.id + ":closing") % len(filteredClosings)
   ```

4. **Собираем текст:**
   ```
   openingText + "\n\n" + [средние блоки] + "\n\n" + closingText
   ```

5. **Хэш-функция** — любая стабильная (FNV-1a, crc32 или SipHash). Главное — одна и та же для одного и того же `planet.id` в любой момент времени.

**Гарантия:** одна планета — один текст навсегда. Разные планеты — разные тексты (с вероятностью коллизии, равной 1/N, где N — число подходящих зачинов).

**Важно:** записи с `requires: []` участвуют в выборе наравне с остальными. Если для планеты подходит 5 записей с тегами и 25 без — выбор идёт по всем 30, теги не дают «веса», только фильтруют.

## 8. Стиль и голос каждого типа

Каждый тип имеет свой характер. Тексты должны его выдерживать.

### `gas_giant` — величие и тайна
- Масштаб: «огромный», «тысячи километров», «миллиарды лет».
- Тайна: то, что скрыто под облаками, недоступно.
- Сравнение с известным: «больше Юпитера», «глубже любого океана».
- **Тон:** торжественный, философский, слегка отстранённый.

### `icy` — тишина и хрупкость
- Холод: не как агрессия, а как покой.
- Медленность: «за столетие смещается на метр», «лёд течёт как река».
- Скрытое: под коркой — океан, жизнь, тайна.
- **Тон:** сдержанный, contemplative, почти шёпот.

### `oceanic` — движение и жизнь
- Вода: как источник и как среда.
- Движение: течения, волны, приливы.
- Жизнь: даже если её нет, она возможна.
- **Тон:** живой, динамичный, иногда — обещающий.

### `volcanic` — агрессия и созидание
- Огонь: как разрушение и как начало.
- Динамика: извержения, потоки, жар.
- Обновление: планета сама себя перестраивает.
- **Тон:** энергичный, иногда — жёсткий.

### `desert` — суровость и время
- Засуха: отсутствие как факт.
- Время: ветер, эрозия, медленное изменение.
- Память: то, что было раньше (реки, озёра, жизнь).
- **Тон:** спокойный, немного меланхоличный.

### `glass` — хрупкость и радиация
- Стекло: как результат катастрофы.
- Отражение: планета как зеркало.
- Опасность: радиация, ожоги, стерильность.
- **Тон:** холодный, отстранённый.

### `metal` — тяжесть и структура
- Металл: как материал и как основа.
- Порядок: слои, структуры, устойчивость.
- Богатство: ресурсы, которые здесь есть.
- **Тон:** технический, точный.

### `organic` — жизнь во всех формах
- Биология: сложная, многогранная, иногда — странная.
- Симбиоз: всё связано со всем.
- Удивление: то, чего мы не ожидали.
- **Тон:** тёплый, наблюдательный.

### `rocky` — обычность и надёжность
- Камень: как база, как основа.
- Простота: без излишеств, но с характером.
- Вариативность: от голой скалы до почти-земли.
- **Тон:** спокойный, рабочий.

### `radioactive` — опасность и энергия
- Радиация: как угроза и как ресурс.
- Свечение: планета светится сама по себе.
- Богатство: редкие элементы, тяжёлые изотопы.
- **Тон:** настороженный, но с интересом.

### `earthlike` — дом
- Жизнь: настоящая, сложная, разнообразная.
- Атмосфера: воздух, которым можно дышать.
- Вода: жидкая, открытая, настоящая.
- **Тон:** тёплый, приветливый, «свой».

## 9. Правила работы

**Формат ответа:**
- Один файл — один ответ.
- 30 записей на файл.
- Всё оборачивать в четыре обратных кавычки (````), чтобы JSON не рвался.
- После каждого файла — ждать «дальше».

**Git:**
- После каждого файла — команды `git add` + `git commit` + `git push`.
- Или накопить несколько файлов и запушить одним коммитом (по договорённости).

**Проверка:**
- После каждого файла — визуальная проверка: все `requires` из утверждённого списка (раздел 3), JSON валиден, нет китайских/английских вставок.
- **Не дублировать** тексты из предыдущих файлов той же папки — проверять вручную.

**Стиль:**
- Научно-популярный, не сухой.
- Без штампов («загадочный мир», «таинственная планета»).
- Разные углы подачи: физика, история, загадка, наблюдение, гипотеза.
- Конкретика лучше абстракции: «толщина корки — километр», а не «очень толстая».
- **Утверждения о жизни — только с тегом `has_biosphere` / `inhabited`.** Нельзя писать «здесь есть жизнь» без тега. Можно: «возможно, здесь есть жизнь», «если что-то здесь живёт, то…».

**Ресурс:**
- 30 текстов за раз — рабочий максимум.
- После 5–6 файлов подряд качество падает. Следить за этим и делать паузы.
