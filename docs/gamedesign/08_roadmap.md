## 8.2. Ближайшие задачи

### 8.2.1. Аномалии как контент

Редкие «нарушения» физики — не баги, а фичи мира. Их надо:
1. **Распознать** (аудит уже делает это, нужно понизить severity для «интересных»).
2. **Описать** (художественный текст, 1–2 абзаца).
3. **Показать** в карточке планеты отдельным блоком.

**Список аномалий-кандидатов (15):**
- `jungles_in_cold` — Криоджунгли (оазис во льду)
- `forests_in_cold` — Морозные леса
- `meadows_in_cold` — Ледяные степи
- `swamps_in_cold` — Мёрзлые топи
- `coral_reefs_in_cold` — Холодные рифы
- `glaciers_in_heat` — Жаркий лёд
- `biosphere_without_water` — Сухая жизнь
- `life_without_water` — Жизнь без воды
- `life_without_temperature` — Экстремофилы
- `lava_in_cold` — Кипящая лава в холоде
- `oceans_in_heat` — Горячие океаны
- `satellite_hotter_than_giant` — Приливный нагрев
- `radioactive_without_zones` — Скрытая радиация
- `population_without_habitable` — Стойкие колонисты
- `hydrogen_in_heat` — Странная горячая H-He

**Как хранить:** JSON-библиотека `config/anomalies.json`. У каждой — title, icon, 2–3 варианта текста (детерминированно выбираются по хэшу planet.id).

**Показ:** отдельный блок в карточке планеты, внизу под описанием. Может быть несколько.

### 8.2.2. LLM-генерация описаний

**Идея:** при создании планеты (в `GeneratePlanets`) генерировать уникальные описания через LLM и сохранять в БД. Детерминизм обеспечен — читается из БД, а не генерится на каждый запрос.

**API на выбор:**
- **Groq** — быстрый, 1000 запросов/день бесплатно.
- **YandexGPT 5 Lite** — 10 млн токенов/месяц, работает из РФ.
- **Google Gemini** — 30 запросов/день.
- **OpenRouter** — 26+ бесплатных моделей.

**Что генерировать:**
- Обычные описания планет (вместо текущих 6 шаблонов).
- Описания аномалий.

**Fallback:** если API недоступен — старая шаблонная `generateDescription()` + библиотека аномалий.

**Архитектура:**
- Пакет `internal/llm/` — обёртка над API.
- Вызов из `GeneratePlanetsForWorld` после генерации планеты.
- Батчи по 100 планет с параллельным запросом.
- Поле `description` уже есть в JSON планеты — не надо миграций.

### 8.2.3. Тонкая настройка генерации

Все хардкод-константы вынести в конфиг, редактируемый через админку:
- Спектральные классы (веса, диапазоны T).
- Планеты (количество, возраст, шансы газовых гигантов).
- Классификатор (пороги).
- Физика (альбедо, парниковые факторы).
- Ядро (пороги массы, диапазоны).
- Композиция (множители по T и воде).

**Хранение:** JSON-дефолты + override в БД (как у матрицы совместимости).

## 8.3. Задачи в бэклоге

### 8.3.1. Безопасность (критично)

- **JWT-секрет в env.** Сейчас хардкод `your-secret-key` в `jwt.go`. Публичный репозиторий = все токены скомпрометированы. Прочитать из `config.Load()`, `log.Fatal` при пустом.
- **Проверка алгоритма в `VerifyToken`.** Сейчас нет проверки `t.Method.Alg()` — уязвимость JWT с `alg: none`.

### 8.3.2. Многопользовательская архитектура

- **Правило проекта:** любая map, доступная из двух горутин, — под мьютексом. См. `docs/CONTEXT.md`, раздел 0.
- **Проверить оставшиеся файлы:** `internal/generator/faction/faction.go`, `internal/generator/galaxy/galaxy.go` (при параллельной генерации).
- **CI с `go vet -race`.** Автоматически ловит гонки при пуше. Отдельная задача — добавить workflow.
- **`Register` race** — обработать `unique_violation` (код 23505 в Postgres), вернуть 409 вместо 500.
- **Кэш текстур в `planet_image.go`** — сейчас пишется, но не читается. При добавлении чтения — обязательно под мьютексом.

9. **Сравнение галактик.** Какая «здоровая», какая перекошена.
