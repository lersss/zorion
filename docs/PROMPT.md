## 1. Что такое Zorion

MMO-песочница с живым самоподдерживающимся миром. Игрок управляет агентом (кораблём, пчелой, персонажем) и влияет на мир через контракты. Архитектура универсальна — не привязана к сеттингу.

- **Стек:** Go 1.21+, PostgreSQL 15+, Redis 7+, Vanilla JS (ES-модули).
- **Деплой:** Docker + Amvera (PaaS).
- **Repository:** github.com/lersss/zorion
- **Module path:** `zorion`

## 2. Правила работы (ВАЖНО)

### Формат ответов
- **Давай файлы целиком, а не фрагменты для замены.** Я копирую полный листинг и заменяю файл.
- **Один файл — один ответ.** После каждого файла жди команду «дальше».

- **Обязательно оборачивай весь листинг в четыре обратных кавычки** (````), чтобы внутренние ``` не рвали блок копирования. Это критично для JSON-файлов.
- **Git-команды всегда давай одним блоком для копирования.**

### Технические ограничения
- **У меня нет Go локально.** Я коммичу в GitHub, Amvera автоматически собирает из master.

- **БД правлю вручную** через psql/pgAdmin. Миграции не применяются автоматически.
- **Все изменения идут в master**, без feature-веток.
- **PowerShell 5 не читает UTF-8** без явного `-Encoding UTF8`. Не пугайся ошибок `ConvertFrom-Json` на русских файлах — это не проблема JSON.

### Стиль общения

## 3. КЛЮЧЕВОЕ ПРАВИЛО: игра многопользовательская

**Zorion — игра с одновременной работой нескольких игроков на одном сервере.**
Об этом надо помнить при **любой** правке кода. Нагрузка одного игрока — не показатель, проблемы начинаются, когда двое (или больше) делают что-то одновременно.

### Что это значит на практике
- **Любая map, к которой могут обратиться две горутины — под мьютексом.** Go убивает процесс при `concurrent map writes`, recover не спасает.
- **Любой синглтон** (`sync.Once`, глобальные managers) — потенциальный источник гонок.
- **Общие рандомы** (`*rand.Rand` на уровне пакета) не потокобезопасны. Мьютекс или локальный `rand.New(...)` на каждый вызов.
- **Сторонние библиотеки** могут быть не потокобезопасны (gorilla/websocket — только одна горутина на запись в соединение).
- **Проверка + действие** должны быть атомарными (`TryStart` вместо `if running + Start`).
- **Долгие операции** (генерация, bcrypt) увеличивают окно гонки.

### Что уже защищено
- `PlanetGenerator.cache/cacheOrder/rand` — `sync.Mutex`
- `WebSocketHub.clients` + запись в conn — `RWMutex` + per-connection мьютекс
- `TravelManager.flights` — `RWMutex` + проверка `current == flight`
- `StatusManager.jobs` — `RWMutex` + `TryStart`
- `CompatibilityMatrix` — `RWMutex`
- `archetypeCache`, `jwtSecret` — только чтение после инициализации
- `*sql.DB` — потокобезопасен

### Что ещё не защищено (долги)
- `Register` в `auth_handlers.go` — race между `GetByUsername` и `Create` (БД защищает, но UX-баг — 500 вместо 409).
- `planet_image.go` — кэш пишется, но не читается. При добавлении чтения — под мьютексом.
- Не проверено: `internal/generator/faction/faction.go`, `internal/generator/galaxy/galaxy.go` (при параллельной генерации).

## 5. Ключевые архитектурные решения (не менять без обсуждения)

- **Композиция вместо типа.** Планета — не один `type`, а набор форм поверхности (16) и типов недр (17) с процентами.
- **Масса первична, размер через плотность.** `R = (M/ρ)^(1/3)`.
- **Ядро — первичная сущность.** Определяет температуру, магнитное поле, геологию.
- **Матрица совместимости.** Симметричная, хранится в БД, редактируется через админку.
- **Все изменения через контракты.** Игрок не может «просто изменить» мир.
- **6 категорий ресурсов:** минералы 🪨, органика 🌿, редкие ⭐, топливо 🔥, вода 💧, газы 💨.
- **Имена — билингвальные.** Кириллица + латиница из одной пары слогов (Атрокс / Atrox).
- **Ресурсы попадают к владельцу**, не в общий пул.
- **Аномалии — фича, не баг.** Редкие «нарушения» физики (джунгли при −50 °C) — интересные находки, с художественными описаниями.

## 7. БИБЛИОТЕКА АНОМАЛИЙ (текущая задача)

### Формат

Один файл на аномалию: `config/anomalies/<code>.json`.
Код совпадает с кодом правила в `internal/audit/planet/`.

```json
{
  "code": "jungles_in_cold",
  "title": "Криоджунгли",
  "icon": "🌿",
  "seeds": [
    "текст 1 (2 абзаца)",
    ... всего 10
  ],
  "tails": [
    "концовка 1 (1 абзац)",
    ... всего 10
  ]
}
```

### Композиция текста

Итоговый текст = **seed + "\n\n" + tail** = 3 абзаца, ~150–200 слов.

### Детерминированный выбор

```js
seedIndex = hash(planet.id + code + ":seed") % 10
tailIndex = hash(planet.id + code + ":tail") % 10
```

Одна планета всегда даёт один и тот же текст. Разные планеты — разные комбинации (10×10 = 100 вариантов на аномалию).

### Стиль текстов

Научно-популярный, 2 абзаца у seed + 1 короткий у tail. С интригой, объяснением «почему так», атмосферой. Без штампов.

**Seeds** — разные углы подачи: физика, экосистема, история, загадка.

**Tails** — 5 «как нашли» + 5 «загадка/тайна». Вторая половина должна интриговать.
