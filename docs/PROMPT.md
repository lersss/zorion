# Промпт для ассистента: проект Zorion

Привет! Я работаю над проектом Zorion. Ниже — контекст, правила и текущее состояние. Прочитай внимательно, это сэкономит нам время.

---

## 1. Что такое Zorion

MMO-песочница с живым самоподдерживающимся миром. Игрок управляет агентом (кораблём, пчелой, персонажем) и влияет на мир через контракты. Архитектура универсальна — не привязана к сеттингу.

- **Стек:** Go 1.21+, PostgreSQL 15+, Redis 7+, Vanilla JS (ES-модули).
- **Деплой:** Docker + Amvera (PaaS).
- **Repository:** github.com/lersss/zorion
- **Module path:** `zorion`

## 2. Правила работы (ВАЖНО)

### Формат ответов
- **Давай файлы целиком, а не фрагменты для замены.** Я часто ошибаюсь при ручной замене кусков.
- **Один файл — один ответ.** После каждого файла жди команду «дальше».
- **Если файл больше 200–300 строк — рефактори и раздели** на несколько логических файлов.
- **Обязательно оборачивай весь листинг в четыре обратных кавычки** (````), чтобы внутренние ``` не рвали блок копирования.
- **Git-команды всегда давай одним блоком для копирования.**

### Технические ограничения
- **У меня нет Go локально.** Я коммичу в GitHub, Amvera автоматически собирает из master.
- **Не спрашивай про локальную сборку** — её не будет. Если что-то падает, я пришлю лог Amvera.
- **БД правлю вручную** через psql/pgAdmin. Миграции не применяются автоматически.
- **Все изменения идут в master**, без feature-веток.

## 4. Ключевые архитектурные решения (не менять без обсуждения)

- **Композиция вместо типа.** Планета — не один `type`, а набор форм поверхности (16) и типов недр (17) с процентами.
- **Масса первична, размер через плотность.** `R = (M/ρ)^(1/3)`.
- **Ядро — первичная сущность.** Определяет температуру, магнитное поле, геологию.
- **Матрица совместимости.** Симметричная, хранится в БД, редактируется через админку.
- **Все изменения через контракты.** Игрок не может «просто изменить» мир.
- **6 категорий ресурсов:** минералы 🪨, органика 🌿, редкие ⭐, топливо 🔥, вода 💧, газы 💨.
- **Имена — билингвальные.** Кириллица + латиница из одной пары слогов (Атрокс / Atrox).
- **Ресурсы попадают к владельцу**, не в общий пул.

## 7. Как мы работаем

1. **Обсуждаем** — если что-то неясно, спрашивай, не угадывай.
2. **Фиксируем в GDD** — если приняли решение, оно идёт в соответствующий файл `docs/gamedesign/`.
3. **Пишем код** — по одному файлу за ответ.
4. **Ты даёшь git-команды** — я копирую, коммичу, пушу.
5. **Ждём сборку Amvera** — если упало, скидываю лог, разбираемся.
6. **Обновляем CHANGELOG и CONTEXT** — после значимых изменений.
